# 投递文案规范

> 本文件负责邮件、AI 案例简答及其他简历外投递文案。网申自我评价、自我描述、个人介绍和求职动机仍由 `self_evaluation/SKILL.md` 负责。

## 1. 输入与原则

先读取目标 JD、该岗位的 Winning Thesis、Supporting Signals、Evidence Map 和相关事实库片段。没有岗位策略时，先完成必要的岗位分析，不直接从通用简历摘句。

- 使用该岗位最强的 1–2 个证据，不简单复制简历；
- 不加入事实库不存在的用户、反馈、业务结果或软能力；
- 按题目字数和沟通场景压缩，不用套话填充；
- 不使用空泛的“学习能力强、责任心强、热爱行业”。

## 2. 邮件

默认只写：身份与申请岗位、最强匹配证据、可到岗时间、留用/长期意愿、附件说明。正文应能在一次屏幕内读完，不展开完整项目过程。

## 3. AI 案例简答

按“问题定义 → 系统设计 → 流程拆分 → 质量控制 → 实际结果与边界”组织。技术名词只有在能解释输入输出、关键选择和验证方式时使用。

## 4. 基金与行业研究岗位

优先说明如何根据研究任务构建 Agent 工作系统，以及系统如何服务研究判断、信息筛选或持续跟踪；数据处理只作为必要支撑，不把工具本身写成核心成果。

## 5. 交付 QA

- 开头直接说明申请对象和最强匹配；
- 每个强表述均能回到事实库；
- 文案与本岗位策略一致，但没有逐字复述 JD；
- 没有把个人项目升级为正式商业产品；
- 没有复制整段简历或堆砌多个弱证据。
